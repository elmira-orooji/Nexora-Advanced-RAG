# جریان‌های اصلی Nexora

این Wireflowها مسیرهای اصلی محصول را پیش از طراحی Wireframe مشخص می‌کنند. هر گره نمایانگر یک صفحه، پنل، دیالوگ یا تصمیم قابل مشاهده برای کاربر است.

## ۱. ورود و شروع کار

```mermaid
flowchart TD
    A[صفحه ورود] --> B{نام کاربری و رمز درست است؟}
    B -->|خیر| C[نمایش خطای ورود]
    C --> A
    B -->|بله| D[Workspace]
    D --> E{کاربر به مجموعه دانش دسترسی دارد؟}
    E -->|خیر| F[Empty state و راهنمای درخواست دسترسی]
    E -->|بله| G[انتخاب گفتگو، مجموعه دانش یا دستیار]
    D --> H[تنظیمات: زبان، ظاهر، رمز عبور]
    H --> D
```

## ۲. بارگذاری و آماده‌سازی سند

```mermaid
flowchart TD
    A[Knowledge base] --> B[انتخاب Knowledge set]
    B --> C[Dropzone یا انتخاب فایل]
    C --> D{نوع و حجم فایل مجاز است؟}
    D -->|خیر| E[پیام ردشدن با دلیل]
    E --> C
    D -->|بله| F[صف بارگذاری]
    F --> G[Queued for processing]
    G --> H[خواندن محتوا]
    H --> I{متن قابل استخراج است؟}
    I -->|خیر| J[OCR در صورت فعال‌بودن]
    I -->|بله| K[تقسیم‌بندی و ایندکس]
    J --> K
    K --> L{پردازش موفق است؟}
    L -->|بله| M[Indexed و اعلان آماده‌شدن]
    L -->|خیر| N[Failed با علت و Retry]
    N --> G
```

## ۳. گفت‌وگوی مبتنی بر منبع

```mermaid
flowchart TD
    A[Conversation] --> B[انتخاب Knowledge set یا Assistant]
    B --> C[تنظیم فیلتر metadata و حالت پاسخ]
    C --> D[نوشتن و ارسال پرسش]
    D --> E[Thinking با امکان لغو]
    E --> F{کاربر لغو کرد؟}
    F -->|بله| G[توقف درخواست و بازگشت Composer]
    F -->|خیر| H[بازیابی قطعه‌های مجاز]
    H --> I{منبع کافی پیدا شد؟}
    I -->|بله| J[پاسخ مستند همراه استناد]
    I -->|خیر| K[پاسخ با پشتوانه ناکافی]
    J --> L[بازکردن Source drawer]
    L --> M[مشاهده فایل، passage و metadata]
    J --> N[کپی، بازخورد یا اشتراک‌گذاری]
    K --> N
```

## ۴. مدیریت تیم و سطح دسترسی

```mermaid
flowchart TD
    A[Team members، فقط مدیر] --> B[فهرست اعضا: مدیران سپس کاربران]
    B --> C[افزودن عضو]
    C --> D[نام کاربری، رمز اولیه، نقش و عنوان]
    D --> E[تخصیص دسترسی Knowledge set]
    E --> F[ذخیره عضو]
    F --> B
    B --> G[ویرایش نقش یا دسترسی]
    G --> E
    B --> H[حذف عضو]
    H --> I{تأیید حذف؟}
    I -->|تأیید| B
    I -->|انصراف| B
```

## ۵. Connector و اعلان وضعیت

```mermaid
flowchart TD
    A[Knowledge set] --> B[Connect source]
    B --> C[انتخاب نوع Connector و تنظیم اعتبارنامه]
    C --> D[اعتبارسنجی اتصال]
    D --> E{اتصال معتبر است؟}
    E -->|خیر| F[نمایش خطا و امکان اصلاح]
    F --> C
    E -->|بله| G[ذخیره و شروع Sync]
    G --> H[خواندن منبع و ایجاد یا به‌روزرسانی اسناد]
    H --> I[پردازش و ایندکس]
    I --> J{Sync موفق است؟}
    J -->|بله| K[اعلان درون‌محصولی موفقیت]
    J -->|خیر| L[اعلان خطا با زمان و علت]
    K --> M[مرکز اعلان‌ها در Workspace]
    L --> M
```

## ترتیب ساخت Wireframe

۱. Login و Workspace؛ ۲. Conversation و Source drawer؛ ۳. Knowledge base و جریان بارگذاری؛ ۴. Assistants؛ ۵. Team members؛ ۶. Settings؛ ۷. نسخه‌های موبایل Conversation و Knowledge base.

Wireframeها باید هر مسیر را با حالت‌های عادی، خالی، درحال‌پردازش و خطا پوشش دهند. برای جزئیات رفتاری و سطح دسترسی، `documents/architecture/USE_CASES.md` و `documents/development/DESIGN.md` مرجع هستند.
